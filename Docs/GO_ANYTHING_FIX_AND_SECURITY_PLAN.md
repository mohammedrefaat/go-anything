# PART B — Security engine

## B.0 Decisions (changes to the original proposal)

| Proposal said | Decision | Why |
|---|---|---|
| Standalone scanner for all Go code, "top-tier scanner for the ecosystem" | **Secondary.** Primary product is the **migration security gate** | gosec, staticcheck, govulncheck, CodeQL, Semgrep are more mature; winning there is a different project |
| "Zero false positives" | **Never claim it.** Every finding carries `confidence` (high/medium/low); docs state the limits | R-6; intra-procedural taint misses flows by design |
| Own offline vuln DB (`vulndb/`) | **Do not build.** Wrap `govulncheck` (already a gate check; it does reachability) | Reinventing it adds maintenance and weaker results |
| `--fix` via `SuggestedFixes` | **Not in v2.1.** Emit textual `fix_hint` only | Almost no fix here is mechanical: `MaxBytesReader` needs a size, `ReadHeaderTimeout` needs a value, `crypto/rand` swaps change API |
| Prompt-injection "guards" for `CLAUDE.md`/`SKILL.md` | Ship as **lint (heuristic)**, named so | Trivially evaded; not a security boundary |
| Differential security parity last (Phase 4) | **Core feature, built on the existing record/replay/fuzz engine** | It is the only capability nobody else has |
| Pre-generation source redaction before the LLM | **Two phases:** warn in v2.1.0 (S8a); redacted view in v2.2.0 (S8b), best-effort, with a container recipe as the real boundary | An agent with disk access reads originals directly; go-anything can't redact what it doesn't mediate |
| New tools expose everything | `audit_code` is **read-only**, output sanitized; **no fix/apply tool over MCP** | R-1 spirit; findings contain source snippets (untrusted data) |

Architecture: shared engine in `internal/audit/`, consumed by (1) a new gate check `security`, (2) CLI `go-anything audit`, (3) MCP `audit_code`. Layering: `rules/` depend only on the analysis API; `audit` use case defines ports (`Loader`, `Reporter`); adapters (SARIF, JSON, console) implement them; CLI handler stays thin.

| Rule ID | Detects | Technical data |
|---|---|---|
| `GA-SQLI` | Query text built from non-constant strings | Calls on `*database/sql.{DB,Tx,Conn}` named `Query/QueryContext/QueryRow/QueryRowContext/Exec/ExecContext/Prepare/PrepareContext` (query arg index 0, or 1 for `*Context`). ### S6 — Differential security parity — P0, L (**the differentiator**)
**Goal:** prove the port still rejects what the original rejects, using recorded and generated *negative* cases. Honest scope (R-6): parity only for those cases.
**Technical data:**
- Add a case tag `security: {class: authn|authz|validation|limits|method|traversal}` (new fields in `schemas/v2`; v1 untouched).
- Generator (reuses the existing differential fuzzer and recorder) derives negatives from the original's **already recorded** positive cases: drop `Authorization`/cookie; tamper token (flip last char); empty body; oversize body (just over the original's observed limit and 10 MiB); wrong `Content-Type`; wrong method; `../` and encoded traversal in path/params; duplicate/odd headers.
- Record the original's response for each mutation (in the sandbox, network off, local instance only, never production), redact, store as `security` cases.
- Replay against the port with the existing `http_contract` comparator in a **status-class** mode: 401/403/400/413/405 on the original must be the same class on the port. A port returning 200 where the original returned 401 is a `GA-PARITY` high finding.
- Gate check `security_parity`: skipped-with-warning when a unit has no security cases; `--require-security-cases` makes it fail closed.
- Report section `security_parity` in the scorecard: cases generated, replayed, diverged, and an explicit "not covered" list.
**Acceptance:**
- [ ] Fixture: original requires a bearer token; a port that forgot the auth middleware fails `gate` with the divergent case.
- [ ] Fixture: correct port passes.
- [ ] Mutations never leave the sandbox/loopback (test asserts the outbound policy blocks non-loopback targets).
